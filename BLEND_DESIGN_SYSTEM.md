# Blend Design System

Blend is Juspay's design system for building connected product experiences
across different brands and contexts. Its goal is not to make every product
look identical: it keeps interactions familiar and predictable while letting
each product retain its character.

> **Guiding idea:** Users should recognize how an interface works, even when
> its visual identity changes.

## Design principles

- **Consistency in behavior:** Keep action hierarchy, interaction patterns,
  and feedback familiar across screens.
- **Adaptable visual identity:** Fit the product's brand and context instead
  of imposing a single visual style.
- **Shared design decisions:** Use design tokens as the connection between
  design and implementation, so colors, spacing, typography, and elevation
  do not need to be reinterpreted for every component.
- **Clear feedback:** Make success, warning, error, loading, and disabled
  states easy to understand and consistent in where and how they appear.
- **Reduced cognitive effort:** Make the primary action, consequences, and
  recovery path apparent, especially in operational or payment-related flows.

## Applying Blend in CollaboNet

The frontend currently has its own Tailwind-based UI components and semantic
theme tokens. This guide describes how to apply Blend's principles in that
codebase; it does **not** mean the Blend React package has been installed or
that existing components have been replaced.

When creating or updating a screen:

1. Reuse existing components from `frontend/src/components/ui` before creating
   a new primitive.
2. Use semantic theme tokens from `frontend/src/styles/theme.css` for text,
   surfaces, borders, focus, and status colors. Avoid hard-coded colors when a
   semantic token is available.
3. Keep typography and spacing consistent with the existing theme and
   typography tokens.
4. Give each screen a clear primary action. Use secondary and destructive
   actions consistently, and make destructive consequences clear before
   confirmation.
5. Provide predictable loading, empty, success, and error states. Keep
   feedback near the action or content that caused it.
6. Preserve keyboard access, visible focus, meaningful labels, and reduced
   motion preferences when building interactions.
7. Prefer small, composable components and avoid introducing a second set of
   global styles or tokens for the same purpose.

### Example interaction checklist

- Is the primary action visually and semantically clear?
- Does the control communicate its hover, focus, disabled, and loading states?
- Does a successful action produce timely, understandable feedback?
- Can a user understand and recover from an error?
- Are destructive or irreversible actions clearly identified?
- Can the flow be completed with a keyboard and assistive technology?

## Official React library

Juspay also publishes `@juspay/blend-design-system`, a React component
library. Its integration uses the package stylesheet and setup generated by
Blend Studio. Follow the upstream guide for current package installation,
provider setup, component APIs, and theming instructions:

1. [Blend Design System website](https://blend.juspay.design/)
2. [Official GitHub repository](https://github.com/juspay/blend-design-system)
3. [Official integration guide](https://github.com/juspay/blend-design-system/blob/dev/APP_GUIDE.md)
4. [Component library README](https://github.com/juspay/blend-design-system/blob/dev/packages/blend/README.md)
5. [Why Blend](https://blend.juspay.design/blog/why-we-named-it-blend/)

Do not add the library or import its global stylesheet as part of an isolated
screen change. Adopting it in this frontend should be treated as a deliberate
integration: check its compatibility with the current React and styling
setup, define how its tokens map to the existing theme, and migrate a focused
screen before replacing shared components.
